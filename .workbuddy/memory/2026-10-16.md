### 关键实现要点

**语法标记自动显隐**（`src/doc/inline.rs` 的核心技巧）：
行内扫描器产出**逐字节连续的样式片段** + 每个构造的定界符范围。渲染时按
光标是否落在该构造的范围内决定是否画定界符。于是平时是干净成品，
光标靠近时语法浮出来，且多个构造各自独立切换，不会连带显形。

**片段合并策略**：只有 `construct` 相同的片段才允许合并，否则逃生符
（`\*`）的定界符与内容会被并成一段，导致它不再被识别为构造。这条是
测试逼出来的。

**容器语法按块独立判定**：`::: tip`（带空格，VitePress）与 `:::note`
（不带空格，Docusaurus）是可判定的真实差异，不能整篇统一判定。若文档
内出现任一方的独有语法（`details` / `caution` / `admonition`），
用它决定整篇默认；都没有则默认 VitePress。

### 修掉的真实缺陷

- PlantUML 箭头解析未做最长匹配：`->x` 先匹配到短前缀 `>`，导致 `x DB`
  被当成参与者名，产生了伪参与者。改为组合箭头优先。
- 行内渲染时按文档坐标切片、却用片段自己的文本取内容，导致渲染文本与
  源文本不一致（光标会错位）。改为统一从源文本切片。

### 环境限制记录

结论：GUI 应用的界面验证交给用户自己跑，比绕限制截图更有效。

## 第二轮：所见即所得模式彻底隐藏语法 + Word 式界面

用户看了截图后提出两条明确要求：**所见即所得模式下不能出现任何 Markdown 符号**，
以及**整体观感要像 Word**。

### 用户偏好（重要）

**所见即所得模式绝不能露出 Markdown 源码。**不是「光标靠近时淡出」，
而是任何情况下都不显示 `**`、`[]()`、`$`、`## `、`- `、`> `。
之前的设计（光标进入构造时定界符淡色显形）被明确否决。
需要看源码时用右下角切换，那是有意的、显式的动作。

### 已完成的改造

- `InlineMode` 枚举取代 `caret: Option<(usize,usize)>` 参数，从类型上消除
  「要不要显形」的歧义。WYSIWYG 与 Source 两种模式显式区分。
- 块标记 `## `、`- `、`> ` 也走 `hidden_format`，此前是可见的。
- 列表改用 Word 式悬挂缩进 + 真实项目符号，嵌套层级用 `• ◦ ▪` 区分。
- 引用块改为竖条 + 斜体正文（新增 `InlineVisual.italic`）。
- 新增页面视图：居中纸张 + 四层投影 + 桌面底色。
- 工具栏改为 Word 式分组功能区（字体 / 段落 / 样式 / 插入）。

### 修掉的两个致命 Bug（用户报「看不到字」）

1. **`hidden_format` 的负字距算错了基数**。原式
   `extra_letter_spacing: -base.font_id.size * 0.9`，而 `base` 是 15.5pt 的
   正文字号，于是每个隐藏字符减 13.95pt。`**bold**` 四个隐藏字符 = -51.8pt，
   整行被拖出页面左侧。教训：隐藏格式的所有度量必须以**隐藏后的字号**为基准，
   不能借用外层字号。正解是干脆不加负字距，1pt 字号本身就足够小。

2. **`ui.horizontal` 默认垂直居中子项**。页面矩形高度等于可用高度，
   居中对齐会把整页上下各推掉一半，文字全部落到视口外。
   必须用 `horizontal_top`，且 `scope_builder` 里显式指定
   `Layout::top_down(Align::Min)`。

另外 `ui.available_height()` 在首帧可能为 0，页面高度需 `.max(320.0)` 兜底，
否则内容被裁掉。

### 测试

从 177 增至 183。新增三个回归测试模块，都是针对本次踩的坑：

- `edit::repro_tests::hidden_delimiters_do_not_destroy_line_width`
  —— 断言 `**bold**` 的排版宽度接近 `bold`，直接锁死负字距 bug。
- `edit::repro_tests::document_text_lands_inside_the_viewport`
  —— 无头渲染整篇文档，tessellate 后遍历所有 mesh 顶点，断言绝大多数
  落在视口内。这是唯一能证明「字真的画出来了」的方法。
- `app::page_tests::geometry_is_always_usable`
  —— `PageGeometry::resolve` 对 0/1/100/280/640/1024/1920/3840/INF/NAN
  都必须给出正值有限数。

### egui 0.37 无头渲染测试要诀

- `Ui::new(ctx, scope_id, ui_builder)` —— 参数顺序是 (ctx, id, builder)，
  且 `CentralPanel::show` 需要父 `Ui`，无头环境要用 `Ui::new` 直接构造。
- `ctx.tessellate(shapes, pixels_per_point)` 返回 `Vec<ClippedPrimitive>`，
  字段是 `primitive`（不是 `primitives`），要匹配
  `egui::epaint::Primitive::Mesh(m)` 才能拿到顶点。
- `FullOutput` 的形状字段叫 `shapes`。
- 排版字形会产生纹理增量，必须 `out.drop_without_applying_deltas()`，
  否则 panic。
- `ctx.fonts_mut(|f| f.layout_job(job))` 返回的 galley 用 `.size().x` 取宽度。

### 架构决定

`PageGeometry` 从 `document_surface` 里抽成纯函数，理由是**页面几何决定每个
字形落在哪里，改错了不会报错、只会白屏**，必须能脱离窗口单测。

## 第三轮：间距、页面高度、行内公式

用户反馈三个问题：页面纸张只覆盖上半截、元素贴得太紧、行内公式显示成字面文本。

### 修掉的问题

**页面纸张高度写死**。原来用 `ui.available_height()` 分配页面矩形，内容超出时
页面不会跟着长，下半截露出桌面色。改为：先用 `ui.new_child` 渲染内容拿到
`min_rect().height()`，再据此计算纸张高度，并把纸张画到 `LayerId::background`
层（否则会盖住刚画好的内容）。最后 `allocate_exact_size` 占位让滚动区随文档增长。

**卡片之间互相重叠**。`card_ui` / `jsx_ui` / `markdoc_ui` 都用
`rect.expand2(pad)` 画背景，但布局只占位了 `rect`，于是每个卡片的背景都溢出到
相邻块的空隙里，加上块间距只有 6pt（正好被 6pt 的背景外扩抵消），视觉上贴死。
改为：padding 作为**布局空间**消耗（`add_space` + `set_width`），背景再用
`expand2` 补齐回同样大小，两者严格一致。

**嵌套块无留白**。`block_ui` 里 `if self.level == 0` 让容器内的子块跳过前导间距，
导致 JSX/Markdoc 容器首尾没有内边距。改为明确区分「顶层块加间距、嵌套块不加」。

**块间距普遍偏紧**：正文 6→10pt、标题 14→26/20pt、盒子类块 14pt。

### 行内公式：真实功能缺口

`content_format` 里 `style.math` 只设了等宽字体和颜色，**`tex::render` 在行内
路径从未被调用**，所以 `$E = mc^2$` 显示成字面文本。块级公式是好的，只有行内坏了。

实现方式（`LayoutJob` 只接受文本，插不进图元）：
1. math span 在 WYSIWYG 模式下替换为**单个占位字符** U+FFFC（OBJECT
   REPLACEMENT CHARACTER），透明、无可见字形、只占一个 char index。
2. 记录 `InlineMathSpan { char_index, source, size, color }`。
3. 排版完成后用 `galley.pos_from_cursor(CCursor::new(CharIndex(i)))` 取到该字符的
   绝对坐标。
4. `paint_inline_math` 在该位置调用 `tex::render` 并叠加图元。

坑：`painter.galley()` 会**消耗** `Arc<Galley>`，所以要先 `Arc::clone` 再绘制。

### 测试（183 → 187）

新增 4 个针对行内公式的测试：识别与替换、多个占位符索引不重叠、源码模式保持
`$…$` 原样、占位符替换不影响同行其他内容。

## 第四轮：编辑状态收尾 + 清掉假开关

用户要求「看看哪里有没有剩下没修的东西，修了构建出来」。工作区里带着上一轮
未提交的改动（切块/切模式/插入块/格式化时丢失正在输入的内容），先验证再收尾。

### 上一轮遗留改动的验证

`cargo test` 209 全绿、`cargo build --release` 通过。新增的回归测试覆盖：
切源码模式保留未提交编辑、切换块后编辑不丢且 span 重定位、任务框勾选、插入块、
中文格式化不切坏 UTF-8、撤销恢复方言与行尾、保存写入活动缓冲区、源码模式快捷键。

### 本轮修掉的真问题

**表格对齐多算了一个内边距**（`edit.rs` 的 `paint_row`）。原式
`x + (widths[c] - pad_x*2) - galley.size().x` 把内边距减了两次，右对齐单元格
实测留白 20pt，而旁边左对齐的是 10pt；居中同样整体偏 10pt。正解是内边距只在
**被推开的那一侧**扣一次。测试用「表格背景矩形的右边缘」当基准（竖分隔线在窄页上
会被裁掉），断言右对齐墨迹距边框恰好 10pt。

**同一处的 `if is_header { text } else { text }`** 是没写完的分支，clippy 的
`if_same_then_else` 抓到的；表头本来就靠粗体 + 单元格底色区分，直接合并。

### 假开关

`Config::show_gutter` / `show_gutter_border` 从来没被渲染层读过：前者在设置里
有个"显示块类型标记"复选框（还默认开启），后者连界面都没有。全库没有任何
`BlockWidgetType` 之类的基础设施，凭空做一个没法目视验证的版式功能风险更大，
所以按"不留假开关"删掉，并补测试确认老配置文件（仍带 `showGutter` 键）能正常加载。

`Config::diagram_font_scale` 是同类死字段，但这个接上了：决定乘到图表字号上，
并在设置里给出「图表字号」滑块。**缓存键必须带上它**，否则改了设置还是显示旧图
（`cache_key` 原来只哈希 code/dark/size）。

### 教训

给"绘制结果"写断言时，基准必须来自**真实绘制出来的图元**，不能拿被测量的那条
公式反推——我第一版测试就是因为用了同一个错误公式当基准而"通过"，等于没测。
另外这个测试我改了四版才立住：表格列宽是内容自适应的（`clamp(48, 320)`），
不能假设列宽。
